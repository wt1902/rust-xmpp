# 0.7.3 — newest-first PEP item retrieval

Журнал0.7.2 показывает успешные SASL/bind, own-account PEP discovery,
чтение и публикацию OMEMO. Ошибок на OMEMO IQ в приложенном фрагменте нет;
есть ошибки avatar metadata у отдельных запросов, но без scope они не
доказывают отказ на собственном аккаунте. Пользователь подтвердил полное
завершение процессов Android-приложений; прежний latch нельзя принимать
за установленную причину.

Найден и воспроизведён дефект выдачи нескольких сохранённых элементов:
сначала выбирались последние N, затем ответ разворачивался ещё раз и
возвращал старый элемент первым. Native Prosody archive_itemstore возвращает
новые первыми. Проверенный monocles IqParser.getItem берёт только первый item;
если старый item содержит пустой список, клиент видит пустой список, хотя
в более позднем item есть устройства и весь IQ имеет type=result.

В0.7.3 устранено лишнее разворачивание ответа PEP/PubSub items. Поиск по ID,
выбор последних N, права доступа, лимиты хранения и сами данные сохраняются.
Native oracle с настоящим mod_pep подтвердил current,old на тех же данных;
сетевая проверка повторяет первый-item parser, замену current и restart.
Regression на исходниках ZIP0.7.2 воспроизводит old,current и ошибку parser.

Уточнена безопасная INFO диагностика: target_scope отличает own-account,
other-account, server/resource/implicit/host-or-component. Для успешного
items result добавлены items_count, first_content_kind, first_device_count.
Имена пользователей/узлов/элементов/устройств и payload не добавляются в поля.
Это структурные счётчики, не криптографическая проверка OMEMO. Событие выдаётся
после local dispatch; ранние ветки routing могут не формировать его.

Наличие нескольких элементов и конкретное содержимое production узлов не
были доступны. Исправленный дефект — подтверждённый сценарий совместимости,
но не доказательство, что он единственный источник индикатора именно этого
устройства. Не внедряется неподтверждённая гипотеза двойного item wrapper:
предоставленный native archive хранит только payload, как и Rust.

DNSSEC повторно проверен публичными DS/DNSKEY запросами: нет Answer, AD=false.
Зона/DS у регистратора не менялись. Инструкция — docs/DNSSEC.md.
Полная замена Prosody пока не подтверждена: docs/COMPATIBILITY.md.
